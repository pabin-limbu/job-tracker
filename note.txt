## login and signup.
- use better auth for this.
- first create a db and cluster > get connection string and keep it in the env file.
- create lib/db.ts and create a function that connect database and export the function.
- create lib/auth/auth-client.ts for client side handling better auth and lib/auth/auth.ts for server side handling better auth.
- in auth.client ts create auth client and provide a base usr which is our base url also provide better auth secret in env.
- better auth secret can be anything in string.
- the auth.ts file use the db.ts to connect database and auth-client use auth to use connected database. these are done internally by betterauth.

## so how auth and auth-client file work.
- when we start our app it does not run AIP file automatically.
- when we call sign-in function from auth-client it request to hit endpoint to server like "/api/auth/router".
- now this router file will execute where it will import auth file and it gets executd.    
code: import { auth } from "@/lib/auth/auth";
      import { toNextJsHandler } from "better-auth/next-js";
      export const { GET, POST } = toNextJsHandler(auth);

- when signin is called and api is hit, api are responsible for sending back the data where it has to handle 
  what kind of request it is like is it a GET or POST and according to the request type the logic is written and 
  response is sent back but in case of better auth we dont have to write the logic ourself rateher betterauth will we just
  to destructure it and send export it.

- so auth is an engine and toNextJsHandler is an helper function / adapter function to connect auth with next.js so while
  connecting it also provide that API handling logic automatically to us.
